# DEADEYE

A low-poly arena FPS that runs entirely in the browser. Six maps, nine weapons,
bots, and peer-to-peer multiplayer — no build step, no server, no asset
downloads beyond a single vendored copy of Three.js.

**Play:** https://chezburgar.github.io/smashforge/deadeye/

---

## What's in it

**Six maps**, each with its own palette, lighting rig and ambience:

| Map | Setting | Character |
|---|---|---|
| DUNE | Desert outpost | Open, long diagonals, a central two-storey ruin |
| DEPOT | Storage facility | Enclosed, container maze under a catwalk ring |
| FROST | Arctic station | Mid-range, a frozen pond you cross at your peril |
| TEMPLE | Jungle ruins | Heavy verticality around a stepped pyramid |
| HARBOR | Container port | Container stacks, a gantry crane, a moored barge |
| ROOFTOP | Night district | Split-level roofs joined by ramps and planks; falling kills |

**Nine weapons** — assault rifle, SMG, shotgun, sniper, marksman rifle, LMG,
pistol, revolver, knife — plus frag grenades. Each has its own recoil pattern,
spread model, range falloff, reload behaviour and synthesised report.

**Bots** with four difficulty tiers. Difficulty changes reaction time, turn
rate, aim error, engagement range and field of view — never damage or health.

**Multiplayer** over WebRTC data channels with no signalling server: the host
generates a lobby code, the guest returns a reply code.

## Controls

`WASD` move · `SHIFT` sprint · `CTRL` crouch · `SPACE` jump · `R` reload
`G` grenade · `V` melee · `1/2/3` weapons · `Q` last weapon · `TAB` scores
`MOUSE1` fire · `MOUSE2` aim · `ESC` pause. All rebindable in Controls.

## How it's built

Everything is generated at runtime — there is not a single texture, model or
audio file in the repository.

- **Geometry.** Maps are authored as a stream of primitives through a builder
  that bakes every vertex into one flat-shaded, vertex-coloured
  `BufferGeometry`. A whole map is a single draw call (7k–27k triangles).
- **Collision.** Yaw-rotated boxes in a flat spatial hash. The player is a
  vertical cylinder, which is rotation-invariant about Y — so every query runs
  in a collider's local frame without the shape deforming. ~2 µs per move,
  ~15 µs per raycast.
- **Navigation.** No hand-authored waypoints. The finished collision world is
  sampled on a grid, each column probed for standable surfaces, and the
  survivors linked where a player could actually walk or drop. Stairs and ramps
  are validated by tracing the surface rather than trusting a straight line.
- **Audio.** Every sound is synthesised with the Web Audio API. Gunshots layer
  a firing-pin transient, a supersonic crack, bandpassed noise with a falling
  filter, and a low oscillator thump; varying five numbers per weapon gives
  each gun a distinct voice.
- **Characters.** Procedural blocky soldiers built from baked limb meshes on a
  small skeleton, sized against a 1.80 m figure so the hitboxes land where the
  model looks.

## Layout

```
index.html            script order matters — plain globals, no modules
vendor/three.min.js   the only dependency, vendored so no CDN is needed
js/core/              util, geometry builder, collision, audio, input
js/world/             props, the six maps, navigation
js/game/              weapons, viewmodel, character, fx, player, bots, game
js/ui/                hud, menus
js/net/               WebRTC peer-to-peer
```

## Running locally

Any static file server will do:

```bash
npx http-server . -p 8123 -c-1
```

Then open `http://localhost:8123/deadeye/`.

`./check.sh` syntax-checks every source file.

## Note on the name

DEADEYE is an original game. It is not affiliated with, derived from, or
built on assets from any other title — all geometry, models, audio and code
here are generated by the code in this repository.
