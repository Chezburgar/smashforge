Play together, with nothing to set up

This is the easy way, and it is built into the client. One of you makes an ordinary singleplayer world and shares it; everyone else joins with a short code. No server to install, no ports to forward, no domain, no certificate.

The catch, so it does not surprise you: the world runs inside the host's browser tab. When the host closes the tab, the world closes for everyone. For a world that stays up on its own, you want a real server instead.

If you are hosting

  1. Launch Orion and make a world

    Press Launch client, then Singleplayer → Create New World. Play it as normal. An existing world works too.

  2. Share it from the pause menu

    Press Esc and choose the option to open the world to other players. The client registers the world with your primary relay (see below) and reports that it is open.

  3. Your friends will just see it

    On their Multiplayer screen your world appears by itself under “Scanning for games on your local network” — the relay is what tells them about it, so they do not need to be on your network or type anything. You can also show a join code from the pause menu if you would rather hand one out.

  4. Stay in the world

    Keep the tab open and stay in the world. You are the server — if you leave, so does everyone else.

If you are joining

  1. Open the same Orion page and launch

    Any device, any browser. Nothing to install.

  2. Go to Multiplayer and wait a moment

    Under your server list you will see “Scanning for games on your local network”. Despite the wording, this is not limited to your house — the client is asking the relay who is sharing a world, so the host's world appears here even if they are on the other side of the planet.

  3. Click the world when it shows up

    That is the whole thing. If the host chose to hide their world, ask them to show the code instead and use that. If nothing appears, you are probably on different relays — compare the primary below.

Sessions are temporary. If the host closes the world and reopens it, joiners need to look it up again.

What to expect the very first time

The client asks three quick questions before you reach the menu. This is normal and only happens once:

After that, launching goes straight to the Minecraft main menu.

Relays 0

A relay is only an introduction service: it puts the two browsers in touch, then the game data goes directly between you. It never holds your world. The primary relay is the one a newly shared world registers with — host and joiner should have the same one reachable.

Run your own server

A normal Minecraft server does not speak WebSocket, so a browser cannot reach it. EaglerXServer is the plugin that adds that: it opens a WebSocket listener alongside your usual port and translates Eaglercraft clients onto your existing server.

Already have a server? You do not need to move worlds or reinstall. EaglerXServer drops into a server you already run, and Java players keep connecting on port 25565 exactly as before.

Pick the right jar

The release page ships several jars. You need EaglerXServer.jar; the rest are optional add-ons.

JarWhat it is
EaglerXServer.jarThe one you need. Works on Bukkit/Spigot/Paper, BungeeCord and Velocity — the same jar detects the platform.
EaglerWeb.jarServes static files (like a client build) over the same port. Optional.
EaglerMOTD.jarRicher MOTD and server-list icons for Eaglercraft clients.
EaglerXRewind.jarLets much older Eaglercraft versions (1.5.2) connect too.
EaglerXBackendRPC.jarAPI for plugins that want Eaglercraft-specific player data.
EaglerXSupervisor.jarCoordinates several proxies sharing one player pool. Large networks only.

Setup

  1. Install the plugin

    Drop EaglerXServer.jar into your server's plugins/ folder and restart once so it writes its config.

    plugins/EaglerXServer.jar
plugins/EaglerXServer/          # created on first start
  settings.yml                  # listeners live here

  2. Turn off online mode

    Eaglercraft players have no Mojang account, so the server must not try to authenticate them. This is required — logins fail without it. 

    # Paper / Spigot — server.properties
online-mode=false

# BungeeCord — config.yml
online_mode: false

# Velocity — velocity.toml
player-info-forwarding-mode = "none"
    With online mode off, anyone can claim any username. Use a whitelist, or EaglerXServer's own authentication, on anything but a server for friends.

  3. Open the WebSocket listener

    In plugins/EaglerXServer/settings.yml, the listeners section defines where browsers connect. Note the port it binds — that number, not 25565, is what players put into Orion. 

    # shape of the generated config — keep the keys it wrote,
# just confirm the address and port
listeners:
  - address: "0.0.0.0:8081"
    tls_enabled: false

    Forward that port on your router or firewall if players are outside your network.

  4. Give it TLS, so browsers will allow it

    This is the step people miss. Orion is served over HTTPS, and an HTTPS page is forbidden by every browser from opening a plain ws:// socket. Your server needs a wss:// address — meaning a real certificate for a real domain.

    Three ways to get one, easiest first:

    # 1. Cloudflare Tunnel — no port forwarding, free certificate
cloudflared tunnel --url http://localhost:8081

# 2. Caddy in front of the listener — automatic Let's Encrypt
play.example.net {
    reverse_proxy localhost:8081
}

# 3. TLS inside EaglerXServer itself — point settings.yml at your
#    own certificate and key, then set tls_enabled: true
    Cloudflare's proxy passes WebSockets through by default, so an orange-clouded DNS record works without extra configuration.

  5. Hand out the address

    Add your server on the Servers tab, press Test to confirm it answers, then use Share to copy a link that adds it to anyone else's Orion in one click.

When it will not connect

SymptomUsual cause
Blocked immediatelyA ws:// address on this HTTPS page. Get a wss:// address — see step 4.
Times outPort not forwarded, or the firewall is dropping it. Confirm the listener port from step 3.
RefusedRight host, wrong port — people often try 25565, which is the Java port, not the WebSocket one.
Connects, then dropsCertificate not trusted (self-signed), or a proxy in front that is not passing WebSocket upgrades.
Kicked at loginOnline mode is still on. See step 2.

Client setup

Orion is the launcher — the menu, the server book, the launch button. The game itself is the EaglercraftX 1.8 bundle, which is Minecraft code and is not shipped with Orion. You point Orion at a bundle once and it remembers.

Where Orion looks

A bundle is two files: classes.js (the compiled game) and assets.epk (its textures and sounds). Orion loads them from the location below — either a folder in this repository, or any HTTPS URL.

Serving from another origin needs CORS headers on that host. A folder inside this site never does, which is why client/ is the default.

Installing a bundle into this site

  1. Get an EaglercraftX 1.8 offline build

    Obtain a build from the Eaglercraft project, and unpack it so you can see classes.js and assets.epk.

  2. Commit them to orion/client/

    orion/client/classes.js
orion/client/assets.epk
orion/client/lang/          # optional extra languages

    classes.js is large. If it is over GitHub's 100 MB file limit, host the bundle elsewhere and paste that URL into the field above instead.

  3. Push

    GitHub Pages redeploys, and Launch client lights up.

What Orion hands the client

On launch, Orion sets window.eaglercraftXOpts before the bundle evaluates — seeding the in-game multiplayer list from your server book, and setting joinServer when you launched into a specific server.
